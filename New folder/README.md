# Power System Fault Detection and Classification
## using Machine Learning (Random Forest & XGBoost)

---

## Problem Statement

Power grid failures cause massive economic losses and public safety risks.  
Early and accurate classification of fault types — Line Breakage, Transformer Failure,
and Overheating — enables faster maintenance response and reduces downtime.

This project trains machine learning models on sensor measurements to automatically
classify the type of fault occurring in a power system.

---

## Dataset Description

| Property | Value |
|---|---|
| Source | Kaggle — *Power System Faults Dataset* |
| File | `fault_data.csv` |
| Rows | 506 records |
| Features | 8 (after cleaning) |
| Target | `Fault Type` (3 classes) |

**Feature columns used after cleaning:**

| Feature | Description |
|---|---|
| `Voltage (V)` | Measured voltage at the fault location |
| `Current (A)` | Measured current |
| `Power Load (MW)` | Active power load |
| `Temperature (°C)` | Ambient temperature |
| `Wind Speed (km/h)` | Wind speed |
| `Weather Condition` | Categorical — Clear / Rainy / Snowy / Windstorm / Thunderstorm |
| `Maintenance Status` | Categorical — Scheduled / Completed / Pending |
| `Component Health` | Categorical — Normal / Faulty / Overheated |

**Target classes:**

| Class | Count |
|---|---|
| Transformer Failure | 171 |
| Overheating | 171 |
| Line Breakage | 164 |

*Classes are well-balanced; no resampling needed.*

---

## Approach

1. **Data Cleaning** — drop duplicates, fill missing values (median/mode),
   drop ID/location columns, one-hot encode categoricals, label-encode target.
2. **Leakage Check** — drop any feature with |correlation| > 0.999 with the target.
3. **Stratified 80/20 Split** — preserves class proportions in train and test.
4. **Models Trained** — Random Forest (200 trees) and XGBoost (200 rounds),
   both with class-balanced sample weights.
5. **Best Model Selection** — by macro F1 on the hold-out test set.
6. **Cross-Validation** — 5-fold stratified CV on the best model.

## How to Run

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Train the model

```bash
python train.py
```

This produces:
- `model.pkl` — saved best model
- `features.json` — feature names, min/max/mean
- `label_classes.json` — class names
- `metrics.json` — evaluation metrics
- `confusion_matrix.png`
- `feature_importance.png`
- `class_distribution.png`

### 3. Launch the web app

```bash
streamlit run app.py
```

Open http://localhost:8501 in your browser.

### 4. (Optional) Deploy to IBM Watson Machine Learning

```bash
cp .env.example .env
# edit .env with your IBM Cloud credentials
python deploy_wml.py
```

## IBM Cloud Usage

### Watson Studio (Jupyter Notebooks)
Use `ibm_cloud_notebook.py` — paste each block separated by `# --- CELL ---`
into a separate Jupyter cell in a Watson Studio project.
The only dependencies are `pandas`, `numpy`, `scikit-learn` and `matplotlib`,
all of which are pre-installed in Watson Studio's default Python 3.10 environment.

### Watson Machine Learning (WML)
`deploy_wml.py` wraps the `ibm-watsonx-ai` SDK to:
1. Store `model.pkl` in a WML repository.
2. Create an online (REST) deployment.
3. Run a test scoring call.

The script is a no-op if `.env` is absent, so it never blocks local development
or the Streamlit app.

> **Note:** You need an IBM Cloud account with a WML service instance and
> a Deployment Space to use `deploy_wml.py`.
> Free tier ("Lite") is sufficient for testing.

## Design Choices & Notes

- **Target detection** is automatic: looks for columns named "Fault Type", "fault_type", etc.
  before falling back to the string column with the fewest unique values.
- **Categorical encoding** uses one-hot (not ordinal) to avoid implying order in
  `Weather Condition`, `Maintenance Status`, and `Component Health`.
- **XGBoost `use_label_encoder=False`** suppresses a deprecation warning present
  in older XGBoost versions.
- The `Train_data.csv` and `Test_data.csv` in the archive folder appear to be a
  *network intrusion* dataset (NSL-KDD), not a power system dataset.
  `train.py` uses only `fault_data.csv`.
